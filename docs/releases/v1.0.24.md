# WS Hub 1.0.24

What changed since 1.0.23. The checklist and the Country column now agree on which country a call is, and a compound FT8 call such as P4/WE9V occupies one Operate line. A person still starts every transmit.

## Updates

**One country for the checklist and the Country column.** When the country file (`cty.dat`) that WSJT-X already keeps is on this PC, both the checklist and the Country column use that file for the same call. Exact calls in the file win. Suffix rules that a prefix cannot express, such as a three-letter KG4 call being the United States, or a trailing `/R` staying a rover, are applied the same way on both screens. Without the file, the Country column uses the builtin list and the DXCC checklist line stays off.

**One Operate line for a compound FT8 call.** WSJT-X prints a call such as P4/WE9V in full on CQ and as `<P4/WE9V>` once it knows the hash. Those are now one row. A DXpedition line such as `K5WVF RR73; YU6DX <P4/WE9V> +04` is filed under the fox, not under `RR73;`. An unresolved hash (`<...>`) does not open a row. A compound CQ has no grid, so the Grid cell stays blank. A home call such as WE9V joins the compound only on the same radio and band within three minutes; a CQ of the bare call stays a different station.

## Installing from this page

**Linux.** Download `wims-1.0.24-linux-x86_64.tar.gz` and unpack it anywhere. Open the folder, open **scripts**, and double-click **Install WS Hub**. If the file manager asks once, choose **Allow Launching**, **Execute**, or **Run**. Then delete the download and double-click **WS Hub**.

**Windows.** Download `wims-1.0.24-windows-x86_64.zip` and extract it to `C:\WIMS`. Open `C:\WIMS\scripts\windows` and double-click **Install-Wims.cmd**. Then double-click **WS Hub**.
