# WS Hub 1.0.34

What changed since 1.0.33. The site server keeps up with a busy band and WS Skim again. A person still starts every transmit.

## Updates

**No more dropped decodes.** On a site server that has heard many stations (a month of 40m FT8 is about 28,000 calls), the server rewrote its whole heard-grids file every time a decode carried a grid, and checked every remembered call each time the Spotted list was drawn. With WS Skim and a busy seat on the same PC, the server fell behind and the PC threw away some WSJT-X and WS Skim packets. Now a new grid is saved in the background within about 20 seconds, and each lookup reads only the station it needs. On the same data, handling one decode went from about 70 ms to under 0.1 ms, and each screen update from about 2 seconds to under a tenth of a second.

**Bigger receive buffer.** The site server asks the PC for a larger buffer for WSJT-X packets, so a burst at the end of a period waits instead of being dropped.

Nothing changed in how transmit, Enable TX, or claims work.

## Installing from this page

**Linux.** Download `wims-1.0.34-linux-x86_64.tar.gz` and unpack it anywhere. Open the folder, open **scripts**, and double-click **Install WS Hub**. If the file manager asks once, choose **Allow Launching**, **Execute**, or **Run**. Then delete the download and double-click **WS Hub**.

**Windows.** Download `wims-1.0.34-windows-x86_64.zip` and extract it to `C:\WIMS`. Open `C:\WIMS\scripts\windows` and double-click **Install-Wims.cmd**. Then double-click **WS Hub**.
