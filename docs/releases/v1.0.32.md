# WS Hub 1.0.32

What changed since 1.0.31. You now decide which PCs may run the station's site server, and moving the site server from one PC to another needs a site password. A person still starts every transmit.

## New

**One site server, and the station owner decides where.** If a site server already answers, every PC uses it and does not start another. This is unchanged.

**This PC may host the site server.** A new setting in **Other tools…** → **Site server (station owner)**. It starts checked on a single PC, or on the PC already running the site server, and unchecked on other seats. On a seat where it is unchecked, the launcher shows only which PC has the site server: there is no Start, no Site server checkbox, and no takeover button. When no site server answers, that seat says **No site server found. The last one was on … Ask the station owner to start it.**

**Site password.** Set it with **Set site password…** in the same place, on each PC that may host. Use the same password on each. Only a scrambled copy is kept on the PC. The password is never written to a log.

**Make this PC the site server.** On a PC that may host, while another PC has the site server, this button asks for the site password and then confirms. The other PC's site server turns **Enable TX** off where WS Hub had started a contact, clears work claims, and stops. Nothing is keyed. This PC then starts its own site server, and the agents on every PC follow it. The new site server starts with no claims, connects to the DX cluster using its own Setup, and fills the roster and decodes again within an FT8 cycle or two. After several wrong passwords, takeover is refused for a minute.

**Two site servers.** If two PCs each end up running a site server, for example after they could not see each other for a while, neither one stops on its own any more. Both PCs, and the site console, show **Two site servers are running. The station owner should pick one.** Pick one with **Make this PC the site server** or **Follow the other**.

## Changes

**Start, Stop and Restart ask first.** On a PC that may host, Start site server asks **No site server answered. Start one on this PC?** Unchecking Site server and Restart site server ask first too, because they affect every PC at the station. Stopping or restarting the site server also turns Enable TX off where WS Hub had started a contact.

**The old PC follows.** After a takeover, the PC that gave up the site server uses the new one and does not start its own again.

**Finding the site server again.** If the site server goes away, the launcher looks for it on the network every so often and uses it when it answers.

## After installing

Install 1.0.32 on the tower and the laptop. On each PC that may run the site server, open **Other tools…** → **Site server (station owner)**, make sure **This PC may host the site server** is checked, and click **Set site password…**. Use the same password on both. Leave the box unchecked on other seats.

## Installing from this page

**Linux.** Download `wims-1.0.32-linux-x86_64.tar.gz` and unpack it anywhere. Open the folder, open **scripts**, and double-click **Install WS Hub**. If the file manager asks once, choose **Allow Launching**, **Execute**, or **Run**. Then delete the download and double-click **WS Hub**.

**Windows.** Download `wims-1.0.32-windows-x86_64.zip` and extract it to `C:\WIMS`. Open `C:\WIMS\scripts\windows` and double-click **Install-Wims.cmd**. Then double-click **WS Hub**.
